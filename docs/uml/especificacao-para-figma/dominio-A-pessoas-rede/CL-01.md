# CL-01 — Classes: Pessoas, Identidade e Rede

Status: **PRONTA PARA VALIDAÇÃO**. Este é modelo de domínio seletivo; não reproduz conta de convite, sessão, hash ou rate limit.

Fontes: [ACADEMICO] slides 16–26, 34, 53–58; [REQUISITO] RF01–05/RF22/RF24/RF30, RN-001–004/RN-009–010; [PERSISTENCIA] SQL V1 tabelas `usuario` a `atribuicao_papel_familiar`, `contato_importante`, `informacao_emergencia`.

## Catálogo de classes

| ID / classe | Responsabilidade e atributos exibidos | Operações exibidas | Evidência |
|---|---|---|---|
| C-A01 `Usuario` | Identidade de acesso. `- nome: String`; `- email: String`; `- tipoAcesso: TipoAcesso`; `- ativo: Boolean`. | `+ autenticar(): ResultadoAutenticacao` [INFERENCIA de RF02]. | RF01/RF02/RF30; `usuario`. |
| C-A02 `PessoaIdosa` | Perfil atendido. `- nome: String`; `- dataNascimento: Date [0..1]`; `- ativo: Boolean`. | `+ atualizarPerfil(): ResultadoAtualizacao` [INFERENCIA de RF03]. | RF03/RF30; `pessoa_idosa`. |
| C-A03 `RedeCuidado` | Contexto operacional de cuidado. `- nome: String`; `- situacao: SituacaoRede`; `- versao: Integer`. | `+ vincularMembro()`; `+ desvincularMembro()`. | RF03/RF04; V1 DB-001/002; `rede_cuidado`. |
| C-A04 `MembroRede` | Vínculo histórico de cuidador à rede. `- categoria: CategoriaMembro`; `- vinculadoEm: DateTime`; `- desvinculadoEm: DateTime [0..1]`. | `+ estaVigente(): Boolean` [INFERENCIA de vigência]. | RF04/RN-004; `membro_rede`. |
| C-A05 `AtribuicaoPapelFamiliar` | Concessão temporal de papel familiar. `- papel: PapelFamiliar`; `- concedidoEm: DateTime`; `- revogadoEm: DateTime [0..1]`. | `+ revogar()`; `+ estaVigente(): Boolean`. | RF05/RN-001/RN-002; `atribuicao_papel_familiar`. |
| C-A06 `ContatoImportante` | Contato contextual ao cuidado. `- nome: String`; `- tipo: String`; `- telefone: String [0..1]`. | `+ atualizarDados()` [INFERENCIA de US-026]. | RF22/US-026; `contato_importante`. |
| C-A07 `InformacaoEmergencia` | Ficha vigente de emergência. `- informacao: String`; `- atualizadaEm: DateTime`. | `+ atualizar()` [INFERENCIA limitada à V1]. | RF24; V1 DB-012/019; `informacao_emergencia`. |

`TipoAcesso`, `CategoriaMembro`, `PapelFamiliar` e `SituacaoRede` são tipos enumerados exibidos como texto, não caixas separadas. Não desenhar herança `Usuario→PessoaIdosa` ou `Usuario→MembroRede`: são papéis/contextos diferentes, sem especialização comprovada.

## Catálogo de conexões

| ID | Origem — destino | Tipo/símbolo/localização | Multiplicidade e leitura | Rótulo / evidência |
|---|---|---|---|---|
| CL01-R01 | `Usuario` — `PessoaIdosa` | Associação contínua, sem ponta. | perto de Usuario `0..1`; perto de PessoaIdosa `0..1`. Uma Pessoa Idosa pode ter conta; uma conta Pessoa Idosa vincula-se a no máximo um perfil. | `titular da conta`; RF30, `uq_pessoa_titular`. |
| CL01-R02 | `PessoaIdosa` — `RedeCuidado` | Associação contínua, sem losango. `PessoaIdosa` **[1] — [0..1]** `RedeCuidado`. | Leitura PessoaIdosa→RedeCuidado: uma Pessoa Idosa pode ainda não ter rede ou ter uma rede V1. Leitura RedeCuidado→PessoaIdosa: cada RedeCuidado pertence a exatamente uma Pessoa Idosa. | `contexto de cuidado`; V1 DB-001/002 e FK `fk_rede_pessoa`; slides 18/24. |
| CL01-R03 | `RedeCuidado` — `MembroRede` | Associação contínua. | perto de Rede `1`; perto de Membro `1..*` quando operacional. Cada membro pertence a uma rede; rede operacional exige Principal e Profissional, não só a multiplicidade visual. | `possui vínculo`; RF04/RN-004/V1 DB-002. |
| CL01-R04 | `Usuario` — `MembroRede` | Associação contínua. | perto de Usuario `1`; perto de Membro `0..*`. Cada episódio pertence a um usuário; um usuário pode ter episódios. | `participa por`; `membro_rede`. |
| CL01-R05 | `MembroRede` — `AtribuicaoPapelFamiliar` | Associação contínua; sem composição. | perto de Membro `1`; perto de Atribuição `0..*`. Cada atribuição é de um membro familiar; membro pode acumular papéis. | `recebe`; RF05/RN-002. |
| CL01-R06 | `RedeCuidado` — `ContatoImportante` | Associação contínua. | perto de Rede `1`; perto de Contato `0..*`. | `mantém`; RF22. |
| CL01-R07 | `RedeCuidado` — `InformacaoEmergencia` | Associação contínua. | perto de Rede `1`; perto de Informação `0..1` vigente. | `possui ficha vigente`; V1 DB-012. |

Símbolos: todas são associações porque as fontes provam vínculo estrutural, mas não ciclo de vida de objeto para composição/agregação. Multiplicidades são lidas nos dois sentidos conforme slides 18/24. Nenhuma dependência ou generalização deve ser desenhada.
