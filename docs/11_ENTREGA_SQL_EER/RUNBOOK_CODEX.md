# Runbook de uma única execução — Codex / Fedora / SQL + EER (#124)

1. `git fetch origin && git switch chore/entrega-sql-eer-v1 && git pull --ff-only origin chore/entrega-sql-eer-v1 && git status --short`. Se houver trabalho local não versionado, preservar. Ler README/CHECKLIST deste diretório. **Não trabalhar no PR #123.**
2. `node scripts/prepare_sql_eer_delivery.mjs --check`; `python3 scripts/validate_sql_prototype.py`. Se fontes divergirem, rodar gerador **sem** `--check`, revisar diffs e checar novamente. Não editar SQL gerado.
3. Em **MySQL 8.4 novo e descartável**, exclusivo da issue #124 e restrito a `127.0.0.1`, importar UMA vez `entrega/sql-eer/01_schema_completo_v1.sql` em banco vazio. Verificar mensagens de execução e engine. **Não** utilizar servidor, volume ou credenciais preexistentes.
4. Executar `entrega/sql-eer/02_validar_34_tabelas.sql` e `SQL_EER_DISPOSABLE_CONFIRMED=YES node scripts/verify_mysql_sql_eer.mjs` com `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_USER`, `DATABASE_PASSWORD` privados no processo local (após `npm ci` se faltarem dependências). Expectativa **34 tabelas, 34 PK, 79 FKs** mais todas as UNIQUE/CHECK do manifesto, InnoDB em cada tabela; discrepância é falha.
5. Testar apenas **casos negativos estruturais mínimos** com fixtures sintéticas e rollback/teardown: FK de membro/categoria, unicidade de rede por idoso, apenas 1 Principal ativo, conclusão por ciclo, medicação por ocorrência, expiração de sessão. **Não** criar 36 suites por US. Regras de permissão e número mínimo de profissionais dependem de transação/serviço; declarar limite se não verificado, não inventar trigger ou política.
6. **ANTES de destruir o MySQL descartável**, abrir **MySQL Workbench → Database → Reverse Engineer** com a conexão local, escolher `rede_de_apoio`, selecionar **todas as 34 tabelas**, importar relações, criar diagrama geral e, se necessário, vistas por domínio. Salvar em `entrega/sql-eer/rede_de_apoio_v1.mwb`, fechar/reabrir e confirmar que as 34 tabelas e FKs constam no modelo (não só no banco). Exportar imagem `.png` ou `.svg`. `03_relacionamentos_referencia.dot`/Graphviz é **apenas referência**, não arquivo .mwb.
7. Se Workbench GUI realmente não estiver disponível, registrar impossibilidade; opcionalmente `dot -Tsvg entrega/sql-eer/03_relacionamentos_referencia.dot -o entrega/sql-eer/relacionamentos_preliminares.svg`. Marcar EER **PENDENTE**; não alegar que .dot/.svg equivale ao Workbench.
8. Criar `entrega/sql-eer/RELATORIO_FINAL.md` só com evidências deste ensaio (comandos, versão 8.4.x, 34 tabelas/79 FKs, êxitos/falhas, arquivo .mwb criado/reaberto, imagem e limitações). Verificar sem segredos. Só então limpar **apenas** recursos próprios, identificados por nome/ID/label. Commitar artefatos no mesmo PR ligado à issue #124, sem merge automático ou deploy.

**Critério:** SQL importado sem erro + verificador real PASS + EER `.mwb` reaberto e legível + rastreabilidade. Se faltou Workbench, entregar SQL e reportar exatamente pendência; não voltar a desenvolver US.
