# Estrutura de Issues no GitLab

## Modelo oficial

RF/RNF → Issue de requisito
US → Issue de história

Uma US possui exatamente um requisito de origem.

Um RF/RNF pode originar várias US.

## Relacionamento

Usar Linked items para relacionar:

RF/RNF
↓
US
↓
Entrega

Não criar Task para substituir User Story.

## Critério de conclusão

Uma issue só deve ser fechada após validação da entrega, não apenas após criação do protótipo.
